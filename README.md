# tree-sitter-xo

A [tree-sitter](https://tree-sitter.github.io) grammar for [Xo](https://github.com/xo-lang/xo), written from the language
specification (`spec/core.md`: lexical structure, types, declarations, statements, patterns, effects, concurrency,
tests and contracts). It gives Neovim, Helix, Zed and any other tree-sitter host syntax highlighting, folding,
indentation and structural selection for `.xo` files.

Packages (0.1.0):

- npm: `npm install @xo-lang/tree-sitter-xo` (Node bindings; scoped, since npm refused `tree-sitter-xo` as too close to
  `tree-sitter-go`);
- crates.io: `cargo add tree-sitter-xo`.

## What it covers

- Every statement, expression, pattern and type form of the grammar summary (spec section 15), generics, `uses` and `!`
  clauses, `requires` and `ensures`, `derive`, `match` guards, `scope` and `select`, test blocks.
- All literal forms: integers, floats, durations, runes, strings with `${expr}` and `${expr:?}` interpolation, multi line
  strings, raw strings (`r"..."`, `r#"..."#`, `r"""..."""`), byte strings, lists, maps and sets.
- Go's newline rule for statement termination, in the external scanner (`src/scanner.c`): a newline ends a statement
  unless the next line starts with `.` (a method chain), `->`, or `uses`, `requires`, `ensures`, `invariant`, `derive`,
  `else`, or, outside a block, `{`.
- Two kinds of expression, because an unparenthesized struct literal may not appear in an `if`, `while`, `for`, `match`,
  `requires` or `ensures` expression (spec 1.4).
- `scope` is an identifier in the grammar (a keyword only before a name, spec 1.4); the query colors it as a keyword only
  in `scope NAME {`.

Known limits: the grammar accepts some code the compiler rejects (it checks syntax, not names or types, and not the naming
rules of spec 1.5), and a few forms the spec calls errors, such as a line that starts with a binary operator, parse as two
statements. `xo check` is the authority.

## Tests

```sh
npm install                      # tree-sitter-cli
npx tree-sitter generate
npx tree-sitter test             # corpus (test/corpus) and highlight assertions (test/highlight)
scripts/parse-repo.sh ../xo      # every .xo file of an Xo checkout: expect no ERROR nodes
```

On the Xo repository at 2026-11-08, `scripts/parse-repo.sh` parses 2488 of 2488 files with no ERROR node. The files left
out are the diagnostic tests (`test/errorcheck`) and the foreign-syntax habit tests (`testdata/habits`), which are invalid
on purpose.

## Editor setup

Highlight capture names follow nvim-treesitter (`@keyword.control`, `@function.call`, `@variable.parameter`, ...). Helix and
Zed map most of them; adjust `queries/highlights.scm` if a theme misses one.

### Neovim (nvim-treesitter)

```lua
vim.filetype.add({ extension = { xo = "xo" } })

require("nvim-treesitter.parsers").get_parser_configs().xo = {
  install_info = {
    url = "https://github.com/xo-lang/tree-sitter-xo",
    revision = "v0.1.0",
    files = { "src/parser.c", "src/scanner.c" },
  },
  filetype = "xo",
}
```

Then `:TSInstall xo` and copy `queries/*.scm` to `~/.config/nvim/queries/xo/` (or add the directory to the runtime path).

### Helix

In `~/.config/helix/languages.toml`:

```toml
[[language]]
name = "xo"
scope = "source.xo"
file-types = ["xo"]
comment-tokens = ["//", "///"]
language-servers = ["xo"]
indent = { tab-width = 2, unit = "  " }

[[grammar]]
name = "xo"
source = { git = "https://github.com/xo-lang/tree-sitter-xo", rev = "99b2cfc2ebb6aa6f52751462415573e86fb41a89" }   # v0.1.0
```

with `[language-server.xo] command = "xo"` and `args = ["lsp"]`. Run `hx --grammar fetch` and `hx --grammar build`, then copy `queries/*.scm` to `~/.config/helix/runtime/queries/xo/`.

### Zed

Zed loads grammars through an extension: an `extension.toml` with

```toml
[grammars.xo]
repository = "https://github.com/xo-lang/tree-sitter-xo"
rev = "99b2cfc2ebb6aa6f52751462415573e86fb41a89"   # v0.1.0
```

and a `languages/xo/` directory holding `config.toml` (`name = "Xo"`, `grammar = "xo"`, `path_suffixes = ["xo"]`,
`line_comments = ["// "]`) and the `queries/*.scm` files.

## Bindings

Generated by `tree-sitter init`: Node (`bindings/node`), Rust, C (`make`), Go, Python and Swift. Checked here: the C library
builds (`make`), the Node binding builds with `node-gyp` and loads (also from the published npm tarball), the Rust crate
builds (`cargo publish --dry-run`), and `go test ./bindings/go` passes; the Python and Swift bindings are generated and
list the scanner but were not built here.
